# ข้อเสนอ: ทะเบียนข้อมูลกลาง (Audit ข้อ P1-10) — **ยังไม่ได้สร้าง รอเจ้าของตัดสินใจ**

เขียนเมื่อ 4 ต.ค. 2026 · Audit สั่งว่า "เสนอก่อน ยังไม่ต้องสร้าง" และ "อย่าเขียนตัวดึงข้อมูลใหม่ทั้งหมดในครั้งเดียว"
สิ่งที่ **ทำไปแล้ว** ในรอบนี้คือส่วนที่ Audit สั่งให้ทำทันที: ตัวตรวจข้อมูล + ชุดทดสอบสูตร (ดูท้ายเอกสาร)

## ปัญหาวันนี้ (ตรวจกับไฟล์จริงแล้ว)

- โฟลเดอร์ `data/` มี 19 ไฟล์หลัก + 12 ไฟล์ "ค่าล่าสุด" + 11 ไฟล์ประวัติ + ไฟล์สัญญาณค่ากีบ แต่ละไฟล์มีรูปร่างของตัวเอง
  หน้าเว็บจึงต้องรู้จักรูปร่างของทุกไฟล์
- **ตัวเลขเดียวกันถูกเก็บซ้ำ 13 ตัวชี้วัด** (รหัสเดียวกัน แหล่งเดียวกัน อยู่ในสองไฟล์; เดิม 14 — สำเนาประชากรหน่วยล้านคนใน `invest.json` เลิกดึงแล้วใน Audit P3-6 เพราะไม่มีหน้าไหนใช้) เช่น
  - GDP ของลาว: `economy.json` และ `compare.json`
  - เงินส่งกลับของแรงงาน: `invest.json` และ `population.json`
  - GDP ต่อคน, FDI, หนี้ต่างประเทศ, เงินสำรอง, ส่งออก, เงินเฟ้อ, สัดส่วนคนเมือง: ไฟล์เดิม และ `compare.json`
- อัตราแลกเปลี่ยนดอลลาร์→กีบอยู่ 6 ที่: ประวัติ BOL รายวัน · ค่าเฉลี่ยรายเดือนของ BOL ใน `economy.json` · ค่าเฉลี่ยรายปีของธนาคารโลก ·
  อัตรากลางอ้างอิง (API) · และสำเนาของ API เดียวกันใน `wages.json` กับ `rubber-daily.json`
- ผลเสีย: ถ้าไฟล์หนึ่งดึงสำเร็จ อีกไฟล์ล้มเหลว สองแท็บจะแสดงตัวเลขคนละตัวโดยไม่มีใครรู้

## สิ่งที่เสนอ: 3 ตาราง

```
sources        แหล่งข้อมูล       id, name, url, license, edition, updated, retrieved
indicators     ตัวชี้วัด          id, name (คีย์ข้อความ ไทย/ลาว), unit, definition, source, code (รหัสที่ต้นทาง), frequency
observations   ค่าที่สังเกตได้     indicator, country, period, value, status
```

- `status` = `actual` (ค่าจริง) · `estimate` (ค่าประมาณของสถาบัน) · `forecast` (คาดการณ์) · `hand` (อ่านด้วยมือจากรายงาน)
  → ป้าย "ค่าประมาณ IMF" / "คาดการณ์" บนหน้าเว็บจะมาจากข้อมูล ไม่ต้องเดาจากปี
- `country` → แท็บ "เทียบเพื่อนบ้าน" และแท็บอื่นอ่านตัวเลขของลาวจากที่เดียวกัน ไม่มีสำเนา
- `period` = ปี (`2025`) เดือน (`2026-08`) หรือวัน (`2026-10-02`) ในช่องเดียว
- หน้าเว็บมีตัวอ่านตัวเดียว เช่น `obs("NY.GDP.MKTP.CD", "LAO")` แทนการรู้รูปร่างของ 19 ไฟล์
- เก็บเป็นไฟล์ JSON เหมือนเดิม (ไม่มีฐานข้อมูล ไม่มีเซิร์ฟเวอร์ ไม่มีค่าใช้จ่าย): `data/registry/sources.json`, `data/registry/indicators.json`
  และ `data/obs/<กลุ่ม>.json` แบ่งกลุ่มตามแท็บ เพื่อให้มือถือโหลดเฉพาะที่ใช้

## แผนย้ายทีละขั้น (แต่ละขั้นจบในตัว หยุดได้ทุกขั้น)

| ขั้น | ทำอะไร | หน้าเว็บเปลี่ยนไหม | ความเสี่ยง |
|---|---|---|---|
| 1 | สร้าง `indicators.json` + `sources.json` จากไฟล์ที่มีอยู่ (สคริปต์อ่านอย่างเดียว) และให้ตัวตรวจข้อมูลเทียบทุกไฟล์กับทะเบียน | ไม่เปลี่ยน | ต่ำมาก |
| 2 | ตัวชี้วัด **ใหม่** (เช่น เงินและธนาคารจาก BOL — ดู `audit-p1-7-missing-indicators-th.md`) เขียนเป็น observations ตั้งแต่แรก | เพิ่มแท็บใหม่เท่านั้น | ต่ำ |
| 3 | ย้ายทีละไฟล์: `compare.json` → `economy.json` → `invest.json` → `population.json` แต่ละครั้งต้องได้ข้อความบนทุกหน้าเหมือนเดิมทุกตัวอักษร (เทียบก่อน-หลังอัตโนมัติ) | ไม่ควรเปลี่ยน | กลาง — ทำทีละไฟล์ มีชุดทดสอบคุม |
| 4 | ลบสำเนา 14 ตัวชี้วัด และสำเนาอัตราแลกเปลี่ยน | ไม่เปลี่ยน | ต่ำ (หลังขั้น 3) |
| 5 | ราคารายวัน (ทอง อัตราแลกเปลี่ยน) — **ไม่แนะนำให้ย้าย** รูปแบบ "ไฟล์ประวัติ + ค่าล่าสุด" ใช้ได้ดีและบอตเขียนทุก 30 นาที | — | — |

ประมาณงาน: ขั้น 1 เล็ก · ขั้น 2 ทำไปพร้อมงานใหม่ · ขั้น 3 เป็นงานใหญ่ที่สุด (4 ไฟล์ × ตัวดึง + หน้าที่ใช้)

## สิ่งที่ทำแล้วในรอบนี้ (แทนการรื้อโครงสร้าง)

1. **ตัวตรวจข้อมูล `scripts/check-data.js`** ขยายจากไฟล์รายวันไปครอบคลุมไฟล์เศรษฐกิจทั้งหมด — รันทุก 30 นาทีและทุกสัปดาห์บน GitHub
   - ชุดตัวเลขรายปี/รายเดือน: ปีและเดือนต้องเรียงและเป็นไปได้ ทุกค่าต้องเป็นตัวเลขในช่วงที่หน่วยนั้นเป็นได้ ทุกชุดต้องมีหน่วยและแหล่งที่อยู่ในรายการ
   - **สำเนา 14 ตัวชี้วัดต้องตรงกันทุกปี** (ตอนนี้ตรงกันทั้ง 167 ค่า) — ถ้าวันไหนเพี้ยน งานบน GitHub จะขึ้นสีแดง
   - ตัวเลขอ่านด้วยมือ (`invest-static.json`): ทุกข้อเท็จจริงต้องชี้ไปยังแหล่งที่มีอยู่จริง ทุกแหล่งต้องมีชื่อ ลิงก์ และวันเผยแพร่ ทุกหมวดต้องบอกวันที่ตรวจล่าสุด
2. **ทดสอบว่าตัวตรวจจับได้จริง `tests/data-check.js`**: คัดลอกข้อมูลไปโฟลเดอร์ชั่วคราว แล้วจงใจทำให้ผิด 29 แบบ (ทีละแบบ) — จับได้ครบทุกแบบ
3. **ชุดทดสอบสูตร `tests/calc.js`** 42 ข้อ: สถานะเป้าหมายแผนรัฐ เส้นคาดการณ์ ดอกเบี้ยจริง การแปลงหน่วย (ทอง เงิน ยาง) ตัวเลือกปีของแท็บเทียบเพื่อนบ้าน ฯลฯ
4. สูตรที่เคยเขียนซ้ำหลายที่ ย้ายมาอยู่ที่เดียว (`js/calc.js`, `scripts/lib/units.js`) — ผลลัพธ์ก่อน-หลังเหมือนกันทุกไบต์

## สิ่งที่ขอให้เจ้าของตัดสินใจ

- **ก.** ทำขั้น 1 (ทะเบียนตัวชี้วัด อ่านอย่างเดียว) ในรอบ P2 — แนะนำ เพราะเสี่ยงน้อยและทำให้หน้า "แหล่งข้อมูล" ของ P2 สร้างจากทะเบียนได้เลย
- **ข.** ทำขั้น 1–4 ทั้งหมด (ย้ายไฟล์เศรษฐกิจเข้าทะเบียน) เป็นงานแยกหลังจบ P2/P3
